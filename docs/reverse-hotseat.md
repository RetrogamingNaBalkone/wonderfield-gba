# POLE2: результаты Ghidra и принятые решения

Анализ выполнен на загруженном `Pole_Chudes_hotseat.rar`, а не по описанию игры.
Ghidra 11.3.2 PUBLIC, headless MZ import, JDK Temurin 21.0.7+6. Автоанализ
восстановил 234 функции. Экспорт: `analysis/hotseat/decompiled.c`,
`listing.asm`, `manifest.json`. Семантические имена не назначались автоматически.
Декомпилятор выдаёт предупреждения о сегментах/стеке; адреса ниже относятся
к образу, загруженному Ghidra с базой 1000:0000.

| Адрес | Подтверждённое поведение |
|---|---|
| 1000:0055 | Загрузка `pole2.lib` через строку 1000:0016; `pole.fnt` и `pole2.pic` |
| 1000:12aa | Реплики ведущего; обращение по номеру игрока; ошибка полного слова |
| 1000:193a | Открытие букв и начисление очков текущему игроку |
| 1000:1dd3 / 229a | Выбор буквы и сектор «+», ветки компьютера и человека |
| 1000:274b | Проверка полного ответа; возврат признака ошибки |
| 1000:2a82 | Имя до 10 символов; сохраняется в таблице текущего участника |
| 1000:2c8e | Чтение числа записей из OVL, пары string[20], вычитание 32 |
| 1000:2f07 | Четыре стадии вращения; фильтра третьего повторного результата нет |
| 1000:3655 | Выбор действия, приза и шкатулки; приз шкатулки 100 очков |
| 1000:46a5 | Торг; деньги или подарок исключают только текущего участника |
| 1000:4c74 | Финальный приз и рекорд именно победителя, имя уже известно |
| 1000:5953 | Главный цикл: восемь стадий; пропуск выбывших; первый участник — ИИ |

В главном цикле активный номер хранится в DS:08a4, стадия — DS:08a6,
статус участника — `DS:[0896 + номер*2]`, счёт — `DS:[089c + номер*2]`.
После неверного слова статус устанавливается в 2, активный номер увеличивается,
серия обнуляется. Это отличается от завершения всей одиночной партии.
Серия DS:05fa увеличивается перед попыткой и сбрасывается на нуле, банкроте
и промахе; «+» в POLE2 не исключён из её счётчика. Шкатулки вызываются перед
следующей попыткой человека при серии 3. После разгаданного слова они не
выдаются. Для трёх людей GBA добавляет безопасное завершение при выбывании
всех: исходный DOS не мог попасть в этот случай, поскольку ИИ не выбывал.

Восемь названий стадий взяты из Pascal-строк 1000:58d9..5927. ИИ начинает
стадию с `Random(стадия+1)*15`; победитель ИИ остаётся, проигравший сменяется.
Человеческие счета в главном цикле обнуляются в начале турнира, а не каждой
стадии. Имена выбывших мест DOS запрашивает заново. На GBA закреплённый состав
возвращается под теми же именами: не требуется снова набирать их на каждой
консоли после стадии.

## Согласованные отличия и параметры

- Сингл 1.1: три раунда, прежние значения по умолчанию и старый словарь.
- Мультиплеер: восемь стадий POLE2.
- Словарь и учёт «+» переключаются перед стартом в любом режиме.
- «Персонажи: Версия 1 / Версия 2» объединяет состав ИИ и его графику.
- Люди со спины обязательны в мультиплеере при обеих версиях персонажей.
- Фильтр третьего одинакового результата оставлен из 1.1 во всех режимах,
  по явному решению пользователя. Он не представляется правилом DOS POLE2.
- Фиксированные 2/3 человека, экран передачи консоли, ввод с GBA и кабель —
  необходимые расширения; сингловые ветки остаются отдельными.
- Записи словаря не очищаются от дублей и не исправляются редакторски.
- Другие стены и деньги внутри шкатулки из POLE2 не заменяют графику сцены 1.1.

Все десять подарков и четыре суммы торга одинаковы. Подробности и полный список
добавленных записей находятся в `analysis/hotseat/*-report.txt` и `*-diff.json`.

Новые изображения извлечены без изменения исходных пикселей в `assets/mp-*`.
При сборке применяется существующий `outlined_resize`: палитровое покрытие,
проекция тонких чёрных штрихов, приоритет обводки на силуэте. Людям назначен
общий масштаб для всех поз, чтобы голова не меняла размер при жесте. Контактный
лист сравнения исходника, nearest-neighbor и фактических пикселей ROM проверен
визуально; исходные 57 спрайтов и их алгоритм сборки не заменялись.
