# Аудит ввода и пропуска анимаций GBA

Проверена рабочая сборка 2.0beta3 с SHA-256 `fc7dad4f9a73392e6d4b73b16439748d345c070cb3c434da824e65665345b342`. Область проверки — от чтения KEYINPUT и VBlank до меню, игровых состояний, анимаций, паузы и кабельных очередей. Физическую консоль и связку консолей по кабелю в этом прогоне не использовали.

## Проверено в mGBA

Для каждого сравнения из одного сохранённого состояния эмулятора запускались два сценария. Контроль — кнопка нажата шесть кадров, затем отпущена. Во втором сценарии после трёх кадров отпускания сигнал возвращался ещё на шесть кадров. Состояние считывалось после восьми дополнительных кадров без ввода. Начальные игровые ситуации задавались в RAM, а переходы выполнял код ROM. Такой тест устанавливает реакцию программы на сигнал. По нему нельзя определить характер сигнала физической кнопки.

| Начальное состояние и кнопка | Обычное отпускание | Повторный сигнал |
|---|---|---|
| Верная буква игрока или выбор позиции на «Плюсе», A | Начинается проход ассистентки | Уже начался новый ход |
| Шкатулка игрока, A | Показан результат | Уже начался новый ход |
| Передача консоли следующему игроку, A | Выбор действия | Барабан уже вращается |
| Ввод последней буквы полного ответа, A | Слово ждёт подтверждения | Ответ отправлен |
| Набор слова, имени рекордсмена или имени участника, A | Введён один символ | Введены два |
| Удаление из имени, B | Удалён один символ | Удалены два |
| Открытие паузы, START | Меню паузы открыто | Игра возобновилась |
| Переключение звука, L | Звук выключен | Звук снова включён |
| Страницы подарка, A | Страница 1 при нумерации с нуля | Страница 2 |
| Раздел об авторах, A | Вторая страница | Возврат в меню |
| Меню режимов, вниз | Сдвиг на один пункт | Сдвиг на два, в том числе при двух кадрах отпускания |
| Ответ ИИ о выборе шкатулки, A | Показан результат | Результат по-прежнему показан |

Общий источник в `src/main.c`, функции `capture_keys`: длительность отпускания A зависит от текущего режима и от того, кто ходит. Для ряда действий игрока она равна нулю. Защита стрелок использует один предыдущий кадр. Для B, START и L аналогичной фильтрации нет. Принятый второй фронт может выполнять самостоятельное действие даже на том же экране. Сбор энтропии отделён от выдачи команд.

## Очереди и кабель

- Локальная очередь сохраняет номер режима. При извлечении на другом экране сбрасываются только A и A_RELEASE. Остальные кнопки могут примениться в новом контексте. Новое предложение в торге, реплика вступления или страница подарка могут вообще не менять номер режима.
- Очередь VBlank имеет 31 пригодный слот. Если очередь заполнена, новое событие отбрасывается, включая A_RELEASE. Если так потерять отпускание, ожидающий его стартовый экран потребует ещё одного цикла нажатия. В обычной партии переполнение в этом аудите не наблюдалось.
- В `src/link.inc` функции `link_sample_input` и `link_queue_remote` передают код кнопки и количество повторов. При смене игрока принимающая очередь очищается. Смена экрана у того же игрока не распознаётся по входному слову. Поэтому задержанная команда теоретически может подтвердить следующую фазу. Это вывод по протоколу, отдельного воспроизведения по кабелю нет.
- Проверки готовности в кабельном лобби и редакторе аватара читают сырой KEYINPUT. Отмена соединения по B в `link_cancel_requested` также опрашивает регистр напрямую. Проверка B действует во время ожидания обмена, поэтому её замену нужно проверять при задержанном пакете. У локального меню и кабельного ввода также разные интервалы автоповтора: 30/12 и 18/5 кадров соответственно.

## Таймер без нажатий

В `spin_tick` разность `scene.now - scene.spin_at` беззнаковая. В mGBA при искусственно заданном начале вращения на три кадра в будущем за два кадра остаток упал с 24 шагов до нуля, игра вышла из вращения. В обычном запуске `start_spin` берёт текущий VBlank. Самопроизвольное появление будущей метки в одиночной партии не установлено. Аналогичные сравнения есть в `message_done`, вступлении и титрах. Прямое сравнение `now < chest_until` при показе результата шкатулки отдельно уязвимо к переполнению счётчика. У выплаты денег и шагов ассистентки проверка будущего срока учитывает знак.

## Приоритет исправлений

1. Задать единое правило повторного нажатия для всех кнопок подтверждения и отмены. Проверять одновременно сохранение быстрого намеренного ввода, ввод последнего символа и переход между экранами при удержании.
2. Привязывать команды к тому действию, на котором они возникли. Отдельно определить правила для навигации, глобальных кнопок, смены реплик внутри одного режима и кабельных пакетов в пути.
3. Проверять приближение к сроку и переполнение часов общим способом. Добавить проверки будущей метки, выхода из паузы и получения кабельного снимка.

## Проверка после исправления

Итоговый ROM имеет SHA-256 `36162b90ff59924f9a0590a20a30012bde3d5dc212ec838b45fa892e0948dec7`. В mGBA сценарии повторного сигнала из таблицы теперь дают тот же результат, что и чистое отпускание. Первое нажатие принимается сразу. Для повторного нажатия A нужно шесть отсчётов VBlank с отпущенной кнопкой, для остальных кнопок — четыре. Проверки очереди, пропавшего события отпускания на заставке и вращения на границе переполнения включены в `scripts/test-input-boundaries.py`.

Прошли 299 проверок управления, а также отдельные сценарии для меню, вступления, открытия букв, шкатулок, торга и выплаты. Тест кабельных функций проверил доставку при разных интервалах обмена и отбрасывание устаревшей команды до отправки, после доставки и перед применением. Проверка на физических консолях и полный прогон двух связанных ядер mGBA остаются открытыми.
