# Мультиплеер и параметры партии

[2.0 Beta1](https://github.com/RetrogamingNaBalkone/wonderfield-gba/releases/tag/2.0beta1) — публичный пре-релиз на основе одиночной игры 1.1.
ROM после сборки текущей ветки: `dist/pole 2.0beta2.gba`.

На заставке **A** сразу открывает «Режим игры»: «Один игрок»,
«Локальный мультиплеер», «Мультиплеер по кабелю» и временную «Проверку связи». Только в локальном
мультиплеере отдельно выбираются 2 или 3 человека; по кабелю состав определяется
автоматически. **B** возвращает на предыдущий экран. **START** на заставке
открывает общее меню со справкой, рекордами и авторами.
Перед стартом выбираются независимые параметры:

| Параметр | Сингл по умолчанию | Мультиплеер по умолчанию |
|---|---|---|
| Словарь | Поле чудес, 495 записей | Поле чудес 2, 686 записей |
| Две шкатулки | v1: Плюс не считается | v2: Плюс считается |
| Персонажи | Версия 1: 6 старых изображений | Версия 2: 8 портретов второй игры |
| Условие победы | Прежние правила | По очкам |
| Число основных раундов | 3 | 3, можно выбрать от 1 до 8 |

Оба словаря доступны в обоих режимах. В ROM единый массив из 686 записей;
выбор старого словаря ограничивает выбор первыми 495, совпадающими по словам и темам
с первой игрой. Дубли, написание и порядок сохраняются.

«Персонажи» одновременно выбирает состав и графику ИИ и доступных аватаров. Версия 2 содержит
Фрекен Бок и Багиру и новые портреты шести прежних соперников. Стены, ведущий,
помощница и остальная сцена остаются в стиле существующего GBA-порта.
По умолчанию человеческие участники изображены со спины из POLE2.LIB;
этот аватар доступен независимо от версии персонажей. Имена до 10 символов: крестовина —
выбор, A — буква, B — удалить, R — пробел, START — готово. Пустое имя, включая ввод
из одних пробелов, вызывает сообщение «Имя не может быть пустым». A или B
возвращают к редактированию без изменения текста. Исходная орфография реплик сохранена.

Имена уникальны в пределах партии. Пробелы по краям удаляются, несколько
пробелов внутри заменяются одним; ввод из одних пробелов равнозначен пустому.
Клавиатура вводит только заглавные буквы. В локальной игре совпадение показывает
«Имя уже занято». A или B возвращают к редактированию, сохраняя текст и курсор;
нажатие закрытия сообщения не добавляет и не удаляет букву. При двух людях
зарезервированы имена всех компьютеров выбранной версии, поскольку конкретный постоянный соперник
выбирается после ввода имён; резерв всего выбранного пула сохранён. При трёх людях этого ограничения нет.
Имена в таблице рекордов не резервируются.

По кабелю имена проверяет хост игры после получения всего состава.
При совпадении имя остаётся у участника с меньшим номером консоли; другой
видит «Имя уже занято» и по A или B возвращается к редактированию. Совпадение
с именем ИИ также требует исправления. Соединение при этом сохраняется,
остальные участники ждут в комнате; старт заблокирован до подтверждения
уникальных имён всеми участниками. START отправляет исправленное имя на
повторную проверку. Имена не обрезаются и не получают автоматических суффиксов.
Стандартные имена соответствуют номерам консолей. Итоговые имена видны
в комнате ожидания и одинаковы на всех консолях. Имя и аватар не заменяют
стабильный ID игрока.

В локальном режиме перед ходом другого человека появляется экран передачи
консоли. Его подтверждение не выполняет игровое действие. Новый владелец
видит себя внизу, следующих по кругу участников — слева и справа. При ходе ИИ
сохраняется перспектива последнего человека. По кабелю перспектива каждой
консоли постоянна. Идентификаторы игроков, очки и порядок ходов не
переставляются вместе с изображениями.

Сингл сохраняет три раунда и прежние правила при стандартных параметрах.
Мультиплеер предлагает три режима: «По очкам», «По очкам с риском»,
«По победам». В режимах по очкам выбирается от 1 до 8 основных раундов.
В режиме по победам — цель от 1 до 5 побед (по умолчанию 3).
По умолчанию — «По очкам», 3 раунда. Классического турнира нет.

| Режим | Победитель партии | Банкрот | ×2 / ×4 |
|---|---|---|---|
| По очкам | Максимальный общий счёт | Теряются только очки текущего раунда | Умножаются только очки текущего раунда |
| По очкам с риском | Максимальный общий счёт | Обнуляется весь счёт | Умножается весь счёт |
| По победам | Первый, набравший заданное число побед | Обнуляется весь счёт, победы сохраняются | Умножается весь счёт |

Общий счёт уже включает текущий раунд: перенос в защищённую сумму не добавляет
очки повторно. Закрывший слово выигрывает раунд, без дополнительного бонуса.
Если все выбыли, раунд расходуется, очки учитываются, победу никто не получает.
В «По победам» партия длится до достижения цели одним из игроков. Очки не
определяют победителя, перестрелки нет. Раунд без победителя не приближает
финиш: все возвращаются и играют дальше. Для троих цель в 5 побед может
потребовать 13 результативных раундов плюс раунды без победителя.
В двух остальных режимах досрочного финиша нет.

При равенстве итоговых очков только оставшиеся лидеры играют перестрелку
на новом слове. Побеждает закрывший слово, независимо от очков перестрелки.
Если все её участники выбыли, перестрелка повторяется тем же составом.
Её очки продолжают общий счёт по правилам выбранного режима. Число основных
раундов перестрелки не расходуют. Первым всегда ходит первый участвующий
игрок в стабильном порядке мест; исключённые из перестрелки пропускаются.

Играют два человека и один постоянный ИИ либо три человека. Все начинают с нуля,
получают очки и победы по одинаковым правилам. Компьютер не меняется между
раундами, может выиграть партию, включая достижение цели по победам или перестрелку по очкам.
Неверное слово, принятые деньги или приз исключают участника только до конца
раунда. Ведущий объявляет «Имя / покидает раунд»; при неверном слове сначала
показывается ошибка. В следующем основном раунде все возвращаются.

Раунды называются «РАУНД N ИЗ M», последний запланированный — «ПОСЛЕДНИЙ
РАУНД», дополнительные — «ПЕРЕСТРЕЛКА». В режиме по победам заголовок —
«РАУНД N». Справа вверху для режимов по очкам показано `N/M`,
для режима по победам — только `N`, включая двузначные номера.
Номер раунда показывается на табло; со второго раунда ведущий говорит
«Следующий раунд». Представление участников проводится только перед первым раундом;
в следующих остаются объявление этапа и темы слова. После завершения ведущий объявляет
победителя либо отсутствие победителя; объявление ждёт A. Затем показывается
отдельный экран промежуточных итогов. Промежуточная и финальная таблицы
используют общую сетку и заголовки «Место / Имя / Побед / Счет»; столбец
«Побед» есть только в режиме по победам. Все три места пронумерованы.
Между раундами рядом с местом появляется треугольник вверх или вниз только
при изменении позиции относительно начала раунда. После первого основного
раунда треугольники не показываются; начиная со второго и в перестрелке
показываются по изменению места. Строки отсортированы
по убыванию общего счёта либо числа побед; равенство разрешается по номеру
игрока, в том числе при сравнении позиций до и после раунда.
В финале сверху показаны подпись «Победитель игры» и крупное имя победителя.
Победитель занимает первое место, включая перестрелку, где его счёт может
быть меньше чужого. Остальные места определяются тем же способом, что и
между раундами. Очки не используются для разрешения равенства побед.
A продолжает: рекламная пауза перед следующим основным раундом,
перестрелка либо прежнее награждение и подарок победителю партии.
После подарка игра возвращается на заставку. Результаты мультиплеера не
записываются в рекорды ни на одной консоли; одиночная таблица сохранена.

Премия в мультиплеере выдаётся перед продолжением серии как человеку, так и ИИ. При
включённом учёте «+» он увеличивает серию; если буква завершила слово,
промежуточная премия не выдаётся. Ноль, банкрот и промах сбрасывают серию.
Фильтр третьего одинакового результата барабана одинаков во всех режимах:
согласованно сохранён из 1.1, в меню не выводится.
Состав десяти призов и суммы торга не изменены.

## Кабель

Нужен многопользовательский **GBA Game Link Cable**, 2 или 3 консоли с
одинаковой сборкой ROM; режим multiboot и кабель Game Boy/Color не реализованы.
В режиме по кабелю сначала выбирается действие:

- **«Создать игру»** — на любой GBA, независимо от разъёма. После установления
  связи первый выбранный создатель получает настройки и открывает лобби.
- **«Подключиться»** — ожидать открытого лобби. До его открытия ввод имени и
  выбор аватара недоступны. Если создателя ещё нет, A позволяет создать игру.

Хостом становится автор первой принятой заявки. Если несколько заявок получены
в одном обмене, выбирается меньший номер порта. Поздние заявки не меняют хоста:
их авторы присоединяются к существующей комнате. При выключенном/неподключённом
партнёре консоли не имеют общей истории нажатий; порядок определяется принятыми
заявками, а не сравнением часов загрузки разных GBA.

Только хост выбирает правила, число раундов, словарь и графику. Пункт «Открыть
лобби» подтверждает эти настройки. Затем **все**, включая хоста, вводят имя и
выбирают аватар из общего набора. Число консолей определяется автоматически:
«2 игрока + компьютер» или «3 игрока». Хост отмечен буквой «Х» в списке.

Игра не начинается автоматически при появлении второго участника: хост нажимает
**START**, когда все готовы. До завершения выбора аватаров и исправления
совпадающих имён старт заблокирован. **B** во время ожидания/настройки возвращает
к «Создать / Подключиться», в том числе до подключения остальных. При вводе имени
B стирает символ. Номер игрока и перспектива определяются портом, а права хоста —
отдельным выбором; создатель не обязан быть игроком 1.

Хост считает правила и RNG и принимает ввод только от текущего участника.
Аппаратная ведущая консоль тактирует кабель; если хост на другом порту, она
пересылает его события остальным. События содержат проверенные изменения
состояния и параметры локальной анимации. Промежуточные сектора барабана,
координаты помощницы, позы и купюры не отправляются на каждом кадре.
Подробнее: [события и локальное оформление](link-events.md).

Участники сверяют fingerprint кода и ресурсов. Ошибка/разрыв прекращает игру
с экраном «Связь потеряна», B возвращает в меню. Настройки зачёта, защищённые
очки, победы, состав перестрелки и итоги синхронизируются. Рекорды не
записываются. Звук локально отключает L.

Проверка выполнена в mGBA: локальные сценарии — через libretro, кабель —
несколько ядер с тестовой моделью SIO (регистры, длительность передачи, IRQ,
идентификаторы). Это не проверка физического кабеля и не проверка штатного
сетевого/кабельного интерфейса графического mGBA. На настоящих GBA ещё нужно
проверить электрический тайминг, устойчивость и задержку при 2/3 устройствах.

## Воспроизводимость

### Устойчивость кабельного обмена

SIOCNT bit 3 сообщает, что устройства включили аппаратный режим multiplayer,
но не подтверждает, что их программы обработали предыдущие данные. Поэтому
фиксированной паузы между словами недостаточно: обработка звука, прерывания
и подготовка контрольной суммы могут задержать ответ. Кроме того, настоящий
GBA очищает SIOMULTI0–3 при начале следующей передачи. Старые непрочитанные
данные при этом теряются.

Обмен использует четыре подтверждаемые фазы с чередующимся номером слова:
младший байт, старший байт, CRC-8/ATM двух байтов, окончательное принятие.
Метки фаз проверяют порядок, CRC проверяет содержимое в обоих направлениях.
При несовпадении ведущий повторяет оба байта в пределах исходного таймаута.
До проверки CRC слово остаётся в буфере; клиент передаёт его игре только после
команды принятия, а окончательное подтверждение публикует основной цикл после
копирования. Повтор принятой фазы не выдаёт игре второе слово. При трёх консолях
ведущий проверяет CRC всех участников до команды принятия.

Это закрывает обнаруженный пробел прежней схемы: правильная метка байта
не гарантировала правильного содержимого. Подмена START содержимым предыдущего
заголовка проходила незамеченной, после чего клиент получал fingerprint,
продолжая ждать START. На прежней ROM тест воспроизводит значения с фотографии:
клиент `код 2, RX 39812, OK 42768`, ведущий `код 3`. Тест намеренно вносит
подмену; источник такого нарушения на физическом кабеле пока не установлен.

Контрольная сумма состояния, проверка сборки и таймаут отключения сохранены.
Цена дополнительных подтверждений — больше передач и задержка обновления,
особенно для первого полного состояния. На всех консолях нужна новая
одинаковая сборка. Прохождение тестов не подтверждает устранение сбоя на железе.

Сверка выполнена с [GBATEK](https://mgba-emu.github.io/gbatek/#siomultiplayermode)
и [SIO lockstep mGBA 0.10.5](https://github.com/mgba-emu/mgba/blob/26b7884bc25a5933960f3cdcd98bac1ae14d42e2/src/gba/sio/lockstep.c).
Тестовая модель теперь также очищает SIOMULTI при старте и позволяет задержать
обслуживание каждого 37-го SIO IRQ клиента. Это проверка устойчивости к
задержкам поверх ядер mGBA, а не физического кабеля или штатного GUI mGBA.

```sh
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link.py --irq-delay 20000 --time-scale 4
```

`--rom` и `--elf` позволяют проверить старую сборку тем же тестом.
`--time-scale` увеличивает время игровых сценариев (по умолчанию 1);
аппаратные длительности передач и таймауты ROM не меняются. В тесте
перестрелки после проверки режима по победам явно включается режим по очкам
с риском: режим по победам завершается достижением цели, а не номером раунда.

### Команды и сценарии

При первоначальном подключении сначала ожидается SD-ready при снятом BUSY,
затем выполняется пробная аппаратная передача. Роль определяется по ID,
выданному аппаратурой после этой передачи, а не по сохранённому уровню SI.
Все устройства могут запросить START: у клиентов этот бит доступен только
для чтения, передачу запускает только ведущая консоль. Пока другой участник
ещё запускает ROM, вводит имя или выбирает аватар, ожидание не ограничено
30 секундами; B отменяет его. Запущенная аппаратная передача имеет отдельный
предельный срок получения IRQ даже до первого принятого слова. После начала
обмена с участником таймаут составляет 30 секунд в комнате и 2 секунды в игре.
Повторы внутри одного слова используют общий срок и не продлевают его.
Вход ведущего первым и клиента первым проверяется с паузой
2400 кадров (около 40 секунд):

```sh
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link.py --scenario 0 --join-order host-first --irq-delay 20000
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link.py --scenario 0 --join-order client-first --irq-delay 20000
```

Если запоздалый SIO IRQ обслуживается уже во время следующей передачи, он
игнорируется до её завершения: при BUSY регистры приёма ещё неполны, а бит
ERROR по спецификации не определён. Тестовая модель проверяет и это, выставляя
ERROR во время BUSY; прежняя модель всегда оставляла его нулевым.

Экран разрыва показывает код этапа и десятичное значение последнего завершённого
SIOCNT. При несовпадении заголовка или сборки RX показывает принятое слово,
OK — ожидаемое (в остальных случаях оба могут быть нулевыми).
CRC — счётчик повторов/отказов по контрольной сумме слова; W — последнее
сырое слово транспорта (на ведущем отправленное, на клиенте принятое).
Коды: 1 — первичная передача и назначение ID, 2 — заголовок/старт пакета, 3 — совпадение
сборок, 4 — ввод и имена, 5 — аватары и статус редактирования, 6 — состояние,
7 — контрольная сумма, 8 — проверка выбранных ролей. Эти данные нужны для диагностики на настоящем GBA;
прохождение модели SIO само по себе не подтверждает исправление на железе.

### Проверки нештатных действий

`scripts/test-link-chaos.py` запускает отдельные процессы с фиксированными
seed и сохраняет параметры, вывод и SHA-256 ROM. ROM замораживается на время
прогона, исполняемые файлы разных прогонов разделены. Матрица проверяет:

- все порядки входа 2/3 устройств и задержки вплоть до 2400 кадров;
- отмену ожидания, повторный вход, отмену на разных этапах первого пакета;
- обрыв цепочки и перезапуск каждой консоли во время игры;
- потерю первого IRQ, задержки и остановку готовности на этапах пакета;
- задержки около двухсекундной границы: 119, 120, 121 и 180 кадров;
- неопределённый SI до первой передачи и ERROR во время BUSY;
- подмену START предыдущим заголовком, повреждения содержимого в обоих направлениях
  при сохранённых метках фаз и нулевом аппаратном ERROR;
- аппаратную ошибку завершённой передачи, повреждение состояния и fingerprint;
- переполнение 32-битного таймера с нормальным перезапуском счётчика с нуля;
- случайные кнопки со звуком и меняющимися задержками IRQ;
- несколько последовательных циклов «игра — сбой/перезапуск — повторный вход»;
- неизменность области рекордов SRAM при успешных и аварийных сценариях.

Для допустимых задержек ожидается продолжение связи. Для отключений и
повреждений — ограниченное время до ошибки и возможность начать новую сессию.
Около границы таймаута допустимы восстановление либо согласованное завершение,
но не зависание. Горячее добавление третьего устройства к уже работающей паре
может потребовать выхода в меню и нового подключения всех участников;
бесшовное добавление в текущий пакет не гарантируется.

```sh
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-chaos.py --jobs 4
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-chaos.py --case 8 --count 3 --target 1 --phase 2
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link.py --native
```

Последняя команда использует штатный драйвер SIO lockstep из libmgba,
без подмены регистров тестовой моделью. Через него проверяются обычные
сценарии имён, партии, подключения и отключения. Это отдельная проверка от
инъекции сбоев; GUI mGBA для неё не требуется.

На настоящем GBA остаются электрические параметры, поведение конкретного
BIOS/картриджа и физического кабеля. Минимальный аппаратный прогон: одна
одинаковая новая ROM на всех устройствах; ведущий входит первым, второй
запускается позже; затем вход в комнату, старт и несколько минут игры со
звуком. Для подтверждения режима на троих нужен отдельный прогон с тремя GBA.
При повторном сбое нужны Код/SIO/RX/OK с каждой консоли. Эмуляторные прогоны
не считаются подтверждением устранения наблюдавшегося на железе сбоя.

`python3 scripts/build-cloud.py` собирает ROM; `MGBA_LIBRETRO=/path/to/core.so`
позволяет запускать имеющиеся проверки на Linux. `scripts/test-multiplayer.py`
проверяет настройки, имена, выбывание, перспективы, восемь основных раундов и «+».
`scripts/test-match-rules.py` проверяет банкрот, множители, зачёт, ничьи,
перестрелки, постоянный ИИ, досрочный финиш и неизменность SRAM.
`scripts/test-link.c` использует ABI установленной libmgba; компилировать с теми
же defines, что библиотека, и передать ROM, число консолей, адреса game/mp/prefs/avatars из ELF.
Отчёты хранятся в `docs/verification`, результаты Ghidra — в `analysis/hotseat`.

`scripts/test-player-names.py` проверяет ввод, окно занятого имени, возврат
по A/B без изменения текста, пробелы, имена ИИ и одинаковые аватары.
`MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link.py` собирает кабельный
тест с определениями ABI из CMake-сборки mGBA и проверяет шесть сценариев имён
для двух и трёх консолей. В том числе проверяются исправление без разрыва связи,
повторная ошибка, блокировка старта и отдельное нажатие START после исправления.

## Аватары и подписи игроков

После ввода имени каждый человек выбирает аватар стрелками и подтверждает A.
B возвращает к имени. «Затылок» выбран по умолчанию и доступен в обеих версиях.
Остальные варианты — шесть персонажей первой игры либо восемь персонажей второй;
выбранная версия определяет и состав, и графику. Аватар заменяет боковую фигуру
человека на сцене, но не его имя, номер или управление. Повторяющиеся аватары допустимы.
Это относится и к совпадению с портретом ИИ: уникальность обеспечивает имя,
а принудительный выбор другого портрета ограничивал бы оформление без изменения правил.
Выбор сохраняется между стадиями и передаётся по кабелю. По кабелю параметры
создателя общие; аватар, отсутствующий в его наборе, не допускается при
подключении. Для полного набора второй игры хост выбирает Версию 2.

В мультиплеере имя каждого бокового участника показано над его плашкой
счёта исходным малым шрифтом 8×8, белым цветом, без обводки,
фоновой полосы, сжатия и переноса. Лимит ввода остаётся 10 символов,
включая пробелы. Короткие имена располагаются над своим счётом; правые
подписи немного сдвинуты вправо. Длинные имена могут перекрывать ручки барабана.

Барабан сдвинут на 4 пикселя влево и на 1 вниз только в мультиплеере;
его размер, рисунок и обозначения не изменены. Боковые аватары подняты
на 8 пикселей. Плашка над аватаром показывает очки под риском: очки раунда
в защищённом режиме и общий счёт в двух остальных. Под аватаром без
поясняющих подписей показан общий счёт в режиме «По очкам» либо число
побед и цель (`2/3`). Число центрируется относительно видимого изображения
и располагается близко к его нижнему краю. В режиме с риском дополнительного
числа нет.

Внизу собраны имя своего игрока, дополнительное число и плашка текущего
счёта, сдвинутая влево от ведущего. Они относятся к владельцу перспективы,
а не к тому, кто сейчас ходит: по кабелю всегда свои, локально меняются
при передаче консоли. Дополнительных выделений хода нет — его показывают
реплики. Имена выбывших сохраняются приглушёнными, портреты скрываются.

Во время самого прохода помощницы боковые имена скрыты, включая остановки
у букв; счета и нижние данные своего игрока остаются. Во время реплики
ведущего перед проходом имена видны. Для сектора «Плюс» проход начинается
без этой задержки, имена скрываются сразу. После завершения или пропуска
по A имена возвращаются. Бабблы, меню выбора, шкатулки и клавиатура могут
временно перекрывать показатели. Меню «Приз / Играем» и «Деньги / Приз»
используют исходный крупный шрифт 8×14 и полную высоту кнопок.
Одиночный интерфейс сцены сохранён. Новые меню используют крупный шрифт
пунктов, серые плашки и рамки главного меню 1.1. В параметрах мультиплеера все шесть пунктов видны на одном экране:
«Правила» (заголовок и значение в двух строках), число раундов, словарь,
две шкатулки, персонажи, старт. Правила и число раундов (либо «Побед для выигрыша») расположены наверху. Одиночный экран сохраняет пояснения
под списком. Вверх/вниз выбирают пункт, влево/вправо или A
переключают версию.
В пояснении словаря указаны количество слов и дополнительные темы. Пояснения
используют единый крупный шрифт; мелкий оставлен для кнопочных подсказок.

Имена сохраняют до десяти знаков. Пятизначные счета
показываются без сжатия исходным шрифтом.
Арифметика защищена от знакового переполнения: техническая граница счёта —
2 147 483 647, последующие начисления на этой границе его не увеличивают.
Это предел целочисленного представления, а не ограничение на пять цифр.

SELECT на странице параметров мультиплеера открывает описание выбранной
настройки. Влево/вправо листают все её варианты, не меняя установку; текущий
вариант отмечен «Выбрано». Повторное открытие начинает с установленного
значения. A, B или SELECT закрывают окно без изменения настроек и позиции
курсора. Для числа раундов или цели побед показано объяснение соответствующего диапазона и условия
завершения, для старта — следующих шагов подготовки. Окна сохраняют серое
оформление и исходный крупный шрифт. Проверка: `scripts/test-options-help.py`.

При запуске заставка строит сетку за 24 кадра (около 0,4 с): сначала
вертикальные, затем горизонтальные линии. Название появляется целиком сразу
после сетки. На 36-м кадре (около 0,6 с) появляются «КАПИТАЛ-ШОУ», версия
и подсказки. A и START доступны с первого кадра. При возврате на заставку
в этой игровой сессии показывается готовый экран без повторной анимации.

`scripts/test-standings.py` проверяет порядок строк и пиксели указателей изменения
места в трёх режимах, равные результаты, банкротство, раунд без победителя,
повторную перестрелку, пятизначный счёт и переход из промежуточных итогов.

`scripts/test-final-standings.py` проверяет финальную таблицу трёх режимов,
равенство результатов, победителя перестрелки с меньшим счётом, победу ИИ,
крупное имя победителя, длинные имена и переход к подарку победителю.

`scripts/test-player-layout.py` проверяет привязку боковых подписей к аватарам,
нижней панели к перспективе, значение плашки очков раунда и приглушение
имени выбывшего в трёх режимах.

`scripts/test-walk-names.py` проверяет видимость имён перед проходом, во время
прохода и сектора «Плюс», естественное завершение и пропуск по A, сохранность
счетов и нижних данных своего игрока.

### Регрессия по фотографии с RX 39812

```sh
# Старая ROM: воспроизвести прежнюю пару ошибок (amount=0 ожидает отказ).
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-chaos.py --case 18 --amount 0 --rom /path/to/old.gba --elf /path/to/old.elf
# Новая ROM: та же подмена должна исправляться повтором и допускать старт игры.
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-chaos.py --case 18 --amount 1
```

Для проверки на настоящих устройствах достаточно сначала повторить исходный
порядок: создатель выбирает «Создать игру», второй запускает ROM и выбирает
«Подключиться». Хост открывает лобби, затем оба вводят имена и выбирают аватары.
После готовности участников хост начинает игру. Если возникнет ошибка,
экран сохраняет этап, SIO, RX/OK и CRC/W. Эти данные позволяют отличить повторное
нарушение содержимого от остановки на конкретной фазе транспорта.

### Временный четвёртый пункт: «Проверка связи»

В меню «Режим игры» добавлен четвёртый пункт, доступный без ввода имени и аватара.
Откройте его на всех подключённых GBA и нажмите A на каждой. Тест проверяет сырой
SIO-обмен отдельно от игрового протокола: ведущий посылает меняющийся 16-битный
образец, остальные возвращают его. Следующий образец отправляется только после
получения правильного эха от всех найденных участников. Образец 0xFFFF пропускается,
поскольку аппаратура обозначает им отсутствующего участника.

Основной экран сообщает, ждёт ли консоль первого ответа, идёт ли обмен без ошибок,
есть ли искажения, изменился ли состав GBA или прекратились ранее получаемые ответы.
Не завершившийся первый запуск показан отдельно от потери уже работавшего обмена. Он показывает число
участников, продолжительность, количество проверенных образцов, искажения данных
и аппаратные сбои. Состояние «ждём другую GBA» само по себе не доказывает поломку
кабеля: на другой консоли ещё может быть не запущен тест.

- **A** запускает или останавливает тест. Остановка сохраняет результат на экране;
  новый запуск обнуляет счётчики. Для повторного теста остановите и запустите все GBA.
- **B** закрывает SIO и возвращает к четвёртому пункту меню.
- Пока тест остановлен, **L/R** меняют скорость (9600, 38400, 57600, 115200 бод),
  **вверх/вниз** — минимальную паузу (около 0.25, 1, 4, 16 мс). Установите одинаковую
  скорость на всех GBA; паузу между передачами задаёт ведущая консоль.
- **SELECT** переключает понятный результат и технические подробности: ID (1–4,
  0 до назначения), число GBA, последний SIOCNT, количество завершённых передач RX,
  проверенных образцов OK, ошибок ERR, ожиданий эха WAIT, таймаутов TO и последние
  отправленные/принятые слова. WAIT сам по себе не является ошибкой: эхо возвращается
  последующей передачей. Длительность аппаратной передачи и перерисовка добавляются
  к выбранной минимальной паузе.

Для первой проверки достаточно штатных 115200 бод / 1 мс и 30 секунд работы.
Если здесь есть ошибки, проблема воспроизводится ниже игрового протокола.
Если сырой тест чистый, а игра всё ещё падает, это сужает поиск, но не доказывает
исправность всех таймингов: нагрузка игры и диагностического экрана отличается.
Само по себе увеличение RX не считается исправной связью: после обрыва ведущий
может продолжать принимать собственные слова. Таймаут контролирует ответы
участников, а подробный экран фиксирует согласованный снимок завершённой передачи.
Тест не меняет настройки партии, имена, рекорды или сохранение.

Автоматические проверки утилиты проходят через настоящие обработчики меню ROM:

```sh
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-diagnostic.py
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-diagnostic.py --native --report build/qa/link-diagnostic-native.json
```

Матрица: 2/3 консоли, все четыре скорости, крайние паузы, запуск ведущего или
клиента первым, остановка одной консоли, таймаут остальных и повторный вход.
Тестовая модель дополнительно вносит неверное эхо и задерживает IRQ. Проверка
штатного драйвера mGBA не подменяет регистры и не вносит ошибок.

### Создание комнаты и подключение

Кабельный parent и хост игры — разные роли. `link_host_device` выбирается один
раз по первой принятой заявке и передаётся всем участникам. Повторные заявки,
в том числе с меньшего номера порта, не перехватывают управление. Новое
соединение сбрасывает выбор. Если хост отключается, партия прекращается;
автоматической миграции хоста нет.

Соединение открывается сразу при выборе «Создать / Подключиться». Локальный
редактор настроек работает только у избранного хоста, а редакторы имён/аватаров
открываются после подтверждения лобби. Нажатие START, подтверждающее имя, не
подтверждает одновременно аватар; отдельный следующий A учитывается даже при
отпускании между сетевыми обменами.

Проверки настоящих обработчиков меню ROM для 2/3 консолей:

```sh
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-roles.py --native
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-roles.py --native --scenario 1 --animations --benchmark
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-roles.py --native --scenario 2 --animations
MGBA_BUILD=/path/to/mgba-build python3 scripts/test-link-chaos.py --host 1
```

Проверяются хосты со всех портов, обе версии графики, ожидание без создателя,
одновременные и поздние заявки, ввод профиля только после открытия лобби, пустые
имена, блокировка старта до готовности, отмена настройки и новая попытка,
а также вход создателя за 40 секунд до остальных. Пакетные тесты отдельно
используют заранее выбранные имена/аватары как фикстуру; реальный пользовательский
маршрут проверяет `test-link-roles.py`.
