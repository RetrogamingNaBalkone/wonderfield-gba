# Документация для разработки

Пути в командах указаны относительно корня проекта.

## Графика и звук

Исходная графика EGA имеет растр 640×350, рассчитанный на экран 4:3. При переносе учтена форма исходного пикселя: горизонтальный коэффициент 35/48. Для персонажей, помощницы и кадров портрета используется уменьшение с учётом площади цветов, прозрачности и чёрного контура. Тонкие линии получают приоритет на границе силуэта; новые цвета не добавляются. Все размеры соблюдают видимые пропорции DOS-игры. В `assets` лежат и неизменённые по размерам извлечённые изображения. Палитра восстановлена с учётом трёх замен, выполняемых DOS-игрой, и переведена в RGB555.

Для прямой речи, букв табло и экранной клавиатуры используется исходный шрифт 8×14 без уменьшения; служебные подписи используют исходный шрифт высотой 8 пикселей. Компактный исходный шрифт высотой 6 пикселей используется только для метки версии 12×6 в правой нижней клетке заставки. Облачко речи рисуется после всех объектов, поэтому барабан и персонажи не могут затереть текст.

Крупная синяя надпись заставки подготовлена отдельно из исходных масок: устранены узкие разрывы в нижних соединениях букв и верхней части последней «с». Уменьшение выполняется один раз с учётом площади штрихов, без новых цветов. Просветы букв и узкая петля заглавной «П» сохранены; извлечённые DOS-ресурсы и маленькие логотипы других экранов не меняются. [Кадр из mGBA в масштабе 4×](media/title-clean.png).

У барабана 32 шага вращения с четырьмя исходными кадрами. Обозначения подготовлены отдельно высотой 12 пикселей, чтобы целиком помещаться в сектор: чёрные цифры находятся на белом фоне, белые — на чёрном. Для всех 512 размещений проверяются контраст подложки и отсутствие пересечений. Исходные значки высотой 16 пикселей остаются в ресурсах. Поля вокруг барабана сокращены; для самого широкого правого игрока оставлен зазор не менее трёх пикселей до отдельной области Якубовича.

Табло состоит из трёх общих рядов высотой 8/16/8 пикселей. Буквы находятся в среднем ряду, закрытые клетки залиты исходным тёмно-серым, открытые — светло-серым. Вложенных рамок нет. В клавиатуре оставлен отступ над глифом, поэтому верхний знак исходной «Й» не сливается с границей клавиши. Портрет поднят на 18 пикселей, до счёта оставлено шесть строк; подпись «ВЫ» и выровненное вправо число разделены.

По отдельному запросу дорисована нижняя часть синей стены. [Новая текстура](../assets/generated/blue-stone-extension.png) создана встроенным imagegen по трём исходным каменным плиткам и приведена к четырём исходным цветам. Она используется только в нижнем поясе высотой 13 пикселей; остальные исходные текстуры не заменялись. [Полный промпт](../assets/generated/blue-stone-extension.prompt.txt), исходный результат генерации и индексированный ресурс сохранены в `assets/generated`.

PC Speaker синтезируется прямоугольной волной через Direct Sound A с частотой дискретизации 32 768 Гц. Учитывается исходный делитель PIT 1 193 181 / частота, работают низкие частоты и паузы. Последовательности выбора буквы, перехода и звуковые проходы восстановлены из Sound/Delay/NoSound. Это программный синтез, WAV в картридже не используется. [Пример звука из mGBA](../docs/media/speaker-demo.wav).

## Сборка

Нужны Python 3 и Zig 0.13.0; сторонние Python-пакеты и devkitARM не требуются. Пути можно передать параметрами:

```powershell
.\scripts\build.ps1 -ZigExe C:\path\to\zig.exe -PythonExe C:\path\to\python.exe
```

Результат: `build/gba/pole.gba`, ELF с символами и карта линковки. Скрипт повторно извлекает ресурсы, генерирует данные картриджа, компилирует Thumb/ARM-код, формирует стандартный заголовок GBA и проверяет его контрольную сумму.

Очистка сборок, кэшей, старых результатов проверок и рабочих проектов Ghidra:

```powershell
.\scripts\clean.ps1 -WhatIf # Посмотреть список удаления
.\scripts\clean.ps1
```

Очистка сохраняет `dist`, исходники, ресурсы, результаты анализа в `analysis` и эталонные DOS-кадры в `build/reference`. Для следующей проверки нужно заново выполнить сборку. Кэш Zig сохраняется между сборками для ускорения; команда очистки удаляет и его. Временные копии DOS-игры и настройки Ghidra удаляются после завершения скриптов, в том числе при ошибке.

`scripts/release.ps1` выполняет сборку и все проверки, затем обновляет `dist/pole 1.1.gba`, сохраняя ROM версии 1.0. В `dist` хранятся ROM; скриншоты, анимация и звук находятся в `docs/media`, отчёты — в `docs/reports`. Архив с ROM, инструкцией, контрольной суммой и материалами проверок создаётся в `build/release/pole-gba-1.1.zip` и удаляется командой очистки. Личные сохранения можно хранить в `saves`.

Для повторения декомпиляции:

```powershell
.\scripts\analyze.ps1 -GhidraHome C:\path\to\ghidra -JavaHome C:\path\to\jdk
```

Ghidra импортирует исходный MZ-файл, анализирует 235 функций, именует восстановленные игровые процедуры и экспортирует C-псевдокод и ассемблер. Проект сохраняется в `build/ghidra/Wonderfield.gpr`. [Описание форматов и адресов](../docs/reverse.md).

## Проверка

В 1.1 маски числовых секторов хранятся в `assets/wheel-digits.json` отдельно от извлечённых DOS-ресурсов. Проверяются штрихи цифр и внутренние просветы нулей во всех 32 фазах, включая прямую правую границу нуля у «10» и «20». Исходные изображения секторов не меняются.

У хода человека появилось меню. START ставит игру на паузу и возвращает обратно; при вводе слова/имени START подтверждает ответ, SELECT ставит на паузу. На паузе SELECT возвращает в главное меню. Таймеры сцен сдвигаются на длительность паузы. При вводе открытые буквы закреплены по позициям, клавиатура блокирует именно открытые буквы, а не предыдущие промахи. Буфер имени и формат SRAM `POL2` прежние.

Сцена денег — отдельное состояние CASH, добавленное после существующих состояний. Накопленное изображение хранится отдельно от кадрового буфера. Исходные 10/100/10000/100000 купюр выдаются с периодом 5,672 мс; темп измерен скриптом `scripts/measure_dos_cash.py` при 5000 cycles. Снимок и счётчик выполняются в памяти изолированной копии DOSBox. Отчёт: `docs/reports/dos-cash-timing.json`.

При пропуске 100 тысяч и миллиона рублей готовая картинка из ROM копируется через DMA. Она подготовлена упаковщиком из исходных купюр; во время нажатия A купюры не пересчитываются. Итоговый рисунок пропуска крупных сумм фиксированный, естественная выдача по-прежнему случайная и без ограничения длительности. Для малых сумм дорисовываются оставшиеся 10/100 купюр. Анимация не расходует игровой RandSeed.

`verify_v11.py` проверяет меню, закреплённые клетки, форму цифр, точность пропуска всех сумм, паузу и естественную выдачу 100 купюр. Флаг `--long` дополнительно проигрывает миллион рублей полностью и сверяет время и каждый пиксель; релиз запускает эту проверку. Материалы 1.1 имеют суффикс `v11`, отчёт — `docs/reports/v11-verification.json`.

[Аудит вычислений и отрисовки](performance-audit.md) содержит замеры неподвижных экранов и приоритеты оптимизации. Профиль можно повторить командой `python scripts/audit_idle.py`.

```powershell
python scripts/verify.py
python scripts/verify_scene.py
python scripts/verify_events.py
python scripts/verify_flows.py
python scripts/verify_stage.py
python scripts/verify_v11.py --long
python scripts/verify_performance.py
python scripts/verify_records.py
```

Проверки используют установленный mGBA Libretro core из `%LOCALAPPDATA%/Programs/mGBA/libretro-20261024/mgba_libretro.dll`. Проверяются прохождение трёх раундов кнопками, повторяющиеся буквы, особые секторы, переговоры о призе, шкатулки, неверное слово, ввод имени, SRAM после сброса, клавиатура и реальный аудиовыход. Редкие ветки запускаются явно обозначенными фикстурами памяти; обычное прохождение выполняется через ввод кнопок.

[Отчёт механики](../docs/reports/verification.json), [визуальные проверки](../docs/reports/visual-verification.json), [кадр игры в масштабе 4×](../docs/media/layout-preview.png), [кадр с клавиатурой](../docs/media/keyboard.png). Визуальные проверки контролируют контуры, сохранность всех штрихов реплик и секторов в кадре PPU, различие «И»/«Й», три ряда табло, серую заливку, зазоры портрета и счёта, появление букв после прохода помощницы и размещение всех шести персонажей. Проверено в mGBA; на физической GBA пока не проверялось.

Компоновка экрана, размеры облачка и темп переходов адаптированы к GBA. Сохраняется последовательность сцен и действий, однако тайминги и координаты не являются покадровой копией DOS. Крупное облачко временно закрывает часть сцены; при вращении барабан виден целиком. Это перенос восстановленной игровой логики на C, а не запуск DOS-программы внутри эмулятора. Подробности: [docs/scene-v2.md](../docs/scene-v2.md).
